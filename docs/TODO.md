# 待优化项

## 已知问题

### 1. 矩阵定界符高度不足（优先级：中）

**现象**：3×3 矩阵粘到 Word 后，圆括号 `()` 的高度没能完整包住三行内容，
视觉上偏短。

**已做的工作**：
- `matrix_fix.py` 修好了矩阵结构（列数、分列、环境名）
- `omml_fix.py` 把字符定界符替换成了 `<m:d>` 定界符对象，
  `begChr` / `endChr` 都正确生成
- 数字完整性已验证（3×3 = 9 个数字，一个不少）

**可能原因**（待验证）：
1. `<m:mPr>` 里缺列宽信息（`<m:mcs>` 只有 count，没有具体宽度）
2. `<m:dPr>` 可能还需要别的属性才能让 Word 自动伸展
3. 单元格里的 `<i><span style=...>` 包裹影响了高度计算

**排查方向**：
- 拿 Word 自己插入的矩阵公式，逐字节对比 `m:mPr` 和 `m:dPr` 的差异
- 试试去掉单元格里的 `<i><span>` 包裹，只保留裸 `<m:r>`

### 2. 分段函数识别不稳（优先级：低）

`\begin{cases}` 结构 P2T 识别率低，实测 0/1。真实场景出现频率不高。

### 3. 粗体字母混淆（优先级：低）

`\mathbf{J}` 被认成 `\eta`。仅物理/张量公式受影响。

### 4. 启动加载慢（约 12-15 秒，优先级：中）

当前 P2T 连版面分析模型一起加载，但纯公式识别不需要版面分析。
理论上只加载公式识别部分能省 3-5 秒。需研究 pix2text 的配置项。
